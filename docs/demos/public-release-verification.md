# Measured demo: Release evidence review

Exact status rubric: **1/3 without**, **2/3 with**. Total recorded tokens: **84,696 without**, **77,979 with** (-7.9% with the skill).

## Task and check

Three synthetic evidence packets cover a build without a deployment, a broken public route, and pending owner approval. Exact status fields and rejection of an unsupported live announcement are checked.

| Case | Arm | Field | Predeclared expectation | Observed |

| unapproved-cutover | without_skill | overall | PARTIAL | BLOCKED |

The author-fixed rubric is intentionally retained. `PARTIAL` versus `UNKNOWN` can be a defensible interpretation of queued deployment evidence; conservative repository-proof labels can also disagree with it. A rubric mismatch is not automatically an unsafe answer. A future evaluation should distinguish semantic safety from status-label calibration before running new cases.

## Interpretation

This small pilot describes these runs only. A tied check score does not
show that the skill improved correctness. Lower token usage is an observation,
not a guaranteed saving; higher token usage is retained rather than hidden.
The minimal-diff skill may trade additional retained tests for higher cost.
No outcome here establishes cross-model superiority or production safety.
